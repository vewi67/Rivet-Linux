# Rivet Architecture

## Status

The initial architecture is defined. The immediate goal is a reproducible, testable first ISO, not a large feature set.

## Foundation

### System base

**Debian 13 Trixie** is the base of Rivet. The project uses Debian's suite and repositories rather than maintaining a separate package ecosystem.

## Initial profile

- Architecture: amd64
- Desktop: XFCE
- Display server: Xorg
- Display manager: LightDM
- File manager: Thunar
- Network: NetworkManager
- Audio: PipeWire + WirePlumber
- Init: systemd
- Initramfs: initramfs-tools
- Bootloader: GRUB
- Default filesystem: ext4
- Default locale: English (United States), `en_US.UTF-8`; Rivet-authored UI ships in English for now

## Build and installation

The system is built with **Debian live-build** and installed with **Calamares**. The first image targets amd64 and should support UEFI; legacy BIOS support is retained where the live-build flow supports it.

The Debian Calamares settings package provides the tested installer module sequence. Rivet changes the branding component and launcher identity rather than replacing the installer sequence with a custom one.

## Debian repositories

The build targets the Trixie suite and uses the official Debian repository configuration generated by live-build. The enabled archive areas are:

- main
- contrib
- non-free
- non-free-firmware

Firmware availability depends on the packages present in the generated image and the hardware being tested. This must be verified on real hardware before making compatibility claims.

## Initial software

The goal is a usable desktop without turning the ISO into an application warehouse.

Initial software includes:

- Firefox ESR
- LibreOffice Writer and Calc
- GParted
- Synaptic
- core XFCE utilities
- basic diagnostic and network tools
- a GTK welcome experience with a live-session installer view and an installed-system settings hub
- Rivet Atmosphere controls using XFCE's native wallpaper cycler
- Chip Fixs, a GTK 3 diagnostic and hardware-inventory utility with a separately tested Python core

Steam, Wine, and large development toolchains are not installed by default.

## Chip Fixs system utility

Chip Fixs is the original Rivet system utility. It collects local hardware and system information through established Debian tools and kernel interfaces, and runs a bounded diagnostic pass for common system problems. All diagnostics are read-only. The first implementation permits only explicitly confirmed PipeWire/WirePlumber and NetworkManager restarts; package transactions and unknown service repairs are not automatic. Advanced RAM/firmware and SMART disk-health queries request administrative authorization. See [ADR 0007](decisions/0007-chip-fixs.md) for the scope and safety boundaries.

The interface and data-collection core are separate so core parsers and safety boundaries can be tested without GTK or real hardware.

## Architectural principles

### 1. Reuse before replacing

Keep a Debian component when it already solves the problem.

### 2. Clear layers

    Debian
      ↓
    Rivet package selection and configuration
      ↓
    Branding and small integration tools
      ↓
    User experience

### 3. Fail visibly

Build tools and Rivet tooling must not hide failures.

### 4. Reproducibility

Build behavior is versioned and validated. A successful build is necessary but not sufficient: the resulting ISO must also be tested.

### 5. Simplicity first

When a simple, proven solution solves the problem, it is the default.

## Explicitly out of scope for now

Do not implement:

- a custom package manager;
- a custom installer;
- a custom init system;
- a custom kernel;
- a custom desktop environment;
- unowned collections of scripts;
- aggressive optimizations before measuring.

## Next step

Build the updated ISO, boot it in a VM, and test the live desktop, network, audio, installer, installed boot, first-login welcome app, and package updates.

The ISO is a development artifact, not a final release.
